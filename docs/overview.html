How a recipe becomes a launch

    

      
1 LoadBuilt-in, config dir, $BERNIE_RECIPES, validate paths. Walks folders. Unique id per layer. A later layer replaces an earlier one.

      
2 ResolveMerge extends: depth first, left to right, then the file.

      
3 OverrideConfig set, then --set. Then validate.

      
4 PlanFill inputs, render env and args, select GPUs: arch, count, one PCIe switch.

      
5 HostROCm paths, tuned-MoE folder of the arch, TunableOp profile (rocBLAS hash + arch). Or container mounts.

      
6 CommandHost: venv python. Container: engine run image, or a compose file.

Life of a run

    
Only run.json is stored. bernie ps derives the state from the process (or container) and /health. exited covers a normal stop and a failure: run bernie doctor --run NAME to tell.

Add a GPU generation (data only)

    
1 Device tableCopy the closest file in internal/machine/gpu/devices/ to <generation>.yaml. Fill arches and PCI ids. List the sources in the header. Run go test ./internal/machine/gpu/.

    
2 FixtureCapture a host with scripts/capture-fixture.sh, or make a -synthetic one with a SYNTHETIC file. Add a gpu test.

    
3 RecipesList the arch in requires.arch. Put arch-only settings in recipes/_fragments/arch/. Use experimental until a real benchmark exists. Run go test ./recipes/....

    
4 Tuning data (optional)tunableop/<arch>/<profile>/ and tuned-moe/<arch>/. Run go test ./internal/serving/tuning/.

    
5 Check on the hostmake check, then bernie doctor: gpu.supported.<gfx> is ok once a validated recipe lists the arch. Steps: extending.md §2.

PCIe link classes (bernie topo)

    

      Class of the path between two GPUs
      
ClassPathFor TP

      
PIXSame PCIe switchBest. Put a TP group here.

      
PXBSeveral switches, no root complexGood.

      
PHBThrough one root complexSlower all-reduce.

      
SYSAcross root complexes or socketsAvoid for TP; check P2P.

    

    
When a recipe does not pin HIP_VISIBLE_DEVICES, bernie picks GPUs of the right arch that share a switch.
